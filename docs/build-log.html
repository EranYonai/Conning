The story so far

Eight short chapters. The dated entries are in the log.

1

The harness was in the wrong place

The day before, Eran had shipped Cortest Harness: a small pi-style agent living inside a test CLI on a lab VM. It worked. Getting there took a wheel build, a sync, a module load, a credentials wizard and a reverse SSH tunnel, because the lab firewall wouldn't let the VM reach the LLM.

Looking back, the redundancy was obvious. Every developer already has a capable agent on their own machine. Why rebuild one on every VM?

Instead of having the CLI on the local remote machine, developers usually prefer to work with their own setup and dev machine. … The interface is 100% agent to agent, so it needs to work in a good, efficient way.Eran, the first message
2

Five voices, told to argue

Eran asked for the plan to go to sub-agents and for them to fight about it. Four got the same brief with different jobs. A product lead owned the first five minutes. A security skeptic owned the threat model. A protocol architect owned every token. A contrarian argued, in the spirit of pi, that none of this needed MCP at all. A fifth agent went off to survey open source.

Product"The first five minutes are the product." Under three minutes from install to the first remote command.
Security"The server is the wall." Prompt injection from remote output, and the agent already has bash as you.
Protocol"Four tools, not fourteen." Exit code first, head and tail, a handle for the rest.
Contrarian"You don't need MCP; ssh exists." ssh config, ControlMaster, 1Password's ssh agent.
3

Everyone gave something up

Round two was rebuttals, and it was where the design was decided. Each voice read the other three and changed its mind in public. Security dropped its encrypted vault file after the contrarian argued that a homemade vault is how projects end up with CVEs. The contrarian dropped "MCP later" once product pointed out that approvals and long jobs need a long-lived process anyway. Product gave up its fifth tool and its favourite word, "rig". Protocol dropped server-side shell sessions as hidden state.

What was left is small: a CLI and an MCP server on one core, four agent tools, secrets as references, and OpenSSH under a config Conning generates itself.

4

Adopt ideas

I trust myself and you more than the open source community. But we very strongly need to adopt good ideas from it.Eran

The survey found nothing that combines a vault that keeps secrets out of the model, a token-lean exec API, and Windows plus Linux targets. It did find good parts. From 1Password and HashiCorp Boundary we took "access without exposure", from Teleport deny-first policy, from OpenHands the timeout that hands control back instead of killing, and from Desktop Commander and E2B job handles with tail reads. One SSH MCP server measured its own 37 tools at about 43.5k tokens, which became our warning.

5

The name nobody could have

All four debaters voted for Patchbay, the routing panel in a studio control room. A registry check found it taken on both PyPI and npm. The replacement came from another kind of control room: the conning tower of a submarine, where "you have the conn" means you're the one steering. Conning was free on both registries, and the CLI reads naturally as conn run lab-win1 -- pytest. The machines kept the plainest name in the room: targets.

6

Locking it in, one question at a time

Eran asked for a walkthrough instead of a document: a summary of each section, then the questions that close it. The first answers pulled the scope in. Conning is a tool for one developer on their own machine, so the team-shareable target file went away. Agents with only bash get the CLI as well as MCP. And the agent should know its own helpers well enough to enrol a new target.

That last answer pushed on a rule all four voices had agreed on: the agent can never add a target. The compromise is that the agent proposes the target, it waits as pending, and Eran confirms it with one keystroke. Eran also cut a round trip: cache the CLI help in the README, so the agent doesn't have to call --help every session.

The sharpest moment was about approvals. Pressing "always allow" on systemctl status must not also allow systemctl stop. Eran's answer was to remember two words, not one, the same lesson as the Cortest read-only mode that leaked through cortest subcommands.

Remember 2 commands prefix. You see why?Eran
7

First contact

M1 is where Conning started touching machines. It still shells out to plain OpenSSH, but never through your ~/.ssh/config. Each target gets a generated config: the host key pinned under its own alias, strict checking, every kind of forwarding off, and one reused connection so a burst of commands costs one handshake. A password never appears on a command line. ssh asks a tiny helper for it, and the helper reads it from the ssh process's environment.

The hard part was long jobs. A test run can outlive an SSH connection, so a command doesn't run inside the session. It runs detached on the target, in its own process group, writing to a file under ~/.conning/jobs. The agent's read asks for bytes from an offset, so it only ever sees new lines. A signal reaches the whole process tree. Old images without setsid or timeout still work, with less protection. The first version had a bug: TERM killed the wrapper before it could record the exit code. The fix keeps the wrapper alive and signals only the command's group.

# the agent asks for something outside the allowlist run(target="lab-lin1", argv=["pytest","-x","tests/smoke"], wait=0) status=pending_approval id=a:7c1e (human runs: conn approve a:7c1e) # you, in a terminal $ conn approve a:7c1e a:7c1e on lab-lin1 pytest -x tests/smoke [a]llow once, [e] always allow 'pytest tests/smoke', [d]eny: e # the agent polls, and only sees new lines read(id="a:7c1e", wait=20) approved a:7c1e: started lab-lin1=j:3fa9 status=running job=j:3fa9 dur=20.0s +41 lines read(id="j:3fa9", wait=60) exit=0 dur=71.4s out=o:3fa9

Eran's rule for this milestone was blunt: mock as much as possible and keep coverage above 95%. The trick that made it honest is a fake transport that runs Conning's real remote scripts with the local sh against a throwaway home directory. The job logic gets tested for real without a server. Getting to 100% found four bugs a happy-path demo would have missed. A failed fan-out start was listed as a job handle. An agent could save a password target with no secret, which then broke the whole target file. Typing "e" on a command that has no rule to remember approved it anyway. A single giant line of output, such as minified JSON, crashed the output cap.

8

What's next

M2 brings the approval to where you already are: a prompt in the agent client, a live conn watch view, and a desktop notification. It also adds the audit log, conn doctor, conn mcp install with rules that stop the agent going around Conning with raw ssh, and detached jobs on Windows. The goal hasn't moved: your own agent, on your own machine, working on a lab VM as easily as on localhost, without ever holding its keys.

The shape, today

Conning runs next to your agent. Everything the agent does goes through four tools. Nothing outside those four tools can reach a target, and the policy behind them lives in code, not in the prompt.

ToolSignatureBehavior
targetstargets(filter?, check?)One line per target: name, OS, shell, tags, mode, last seen. Never a host, a user or a secret.
runrun(target, cmd|argv, cwd?, wait=30, timeout=3600, max_bytes=8192, grep?)One target, a list, or tag:x. Exit code first, output capped at 8 KB. Past wait it returns a job handle and the command keeps running.
readread(id, wait?, range?, grep?, signal?)Long-polls a job for new lines (j:), slices saved output (o:), checks an approval (a:), or pages a remote file (target:path).
transfertransfer(source, dest)Copies files between your machine and a target over the open connection and checks the sha256. File contents never enter the model's context.

#5 · M1: commands over SSH 2026-10-14

The four tools now work against real machines. run starts a detached job and returns the exit code first, or a job handle once wait runs out. read streams new lines, sends signals, pages saved output and reads remote files. transfer copies with scp and checks the sha256. On the human side, conn add, approve, import, test, rm and lease work, and host keys are pinned when you approve a target. Secrets are redacted from all output, along with their base64, URL-encoded and hex forms. It was checked end to end against a local sshd (D24 to D27). Eran then asked for unit tests with mocks and 95%+ coverage. There are now 138 tests at 100% coverage, and CI fails below 95%. Writing them found four bugs, all fixed.

#4 · The repo and the M0 scaffold 2026-10-14

The repo landed on GitHub, not GitLab: EranYonai/Conning, Apache-2.0 for its patent grant. The first draft PR scaffolds v0.0.1. It adds the conn CLI, an MCP server with exactly four tools, a fail-closed target file, the output cap, and two-word allowlist rules. Tests keep the README's CLI help in sync with the code, and another caps the size of the tool schemas, about 3 KB today. CI runs on Linux, Windows and macOS, and PyPI releases go through Trusted Publishing. Running commands over SSH is M1.

#3 · Walkthrough, part two 2026-10-14

Tools locked at four, with plain text by default (D5, D17). Eran turned the 8 KB cap into an argument the agent can raise (D14) and asked for progress and async. Claude explained that the model only sees a tool call when it returns, so progress streams to the human while the agent long-polls for new lines (D15). Async came from wait=0 (D16), with no new tool. New lab targets start in ask (D8). Eran asked what "always allow" remembers, then set it to the first two words: "You see why?" The verb is where the danger lives (D18). Transport is SSH-only, and Windows hosts without OpenSSH get a fix the agent relays to the user (D19). Passwords are first-class (D20).

#1 · Idea, debate, design page 2026-10-14

Eran's idea: a control room MCP that vaults credentials for remote test machines and lets a developer's own agent run commands there. Four sub-agents (product, security, protocol, contrarian) wrote positions and then rebutted each other. A fifth surveyed open source: SSH MCP servers, credential brokers, Ansible and pyinfra, WinRM libraries, and agent sandboxes. By round two the four had converged on the shape in this log. A registry check retired Patchbay and Conning took its place. The first design page was published with mocks of onboarding, the agent's view, the watch view and the target file.
