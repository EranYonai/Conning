# Conning

**A control room for your agent's test machines.** Your agent (Claude Code, Codex, Cursor...) stays on
your own laptop. Conning holds the keys to your lab VMs and gives the agent four lean tools to run
commands and move files there. The agent never sees a password, and you approve anything risky.

> **Status: pre-alpha (M1).** Running commands, long jobs, remote file reads and transfers work over
> OpenSSH, with pinned host keys, password or key auth, approvals and leases. Windows targets run
> synchronously for now. `conn watch`, `doctor` and `mcp install` come in M2. See
> [docs/design.md](docs/design.md) for every decision so far.

## Why

Putting an agent harness inside every CLI on every remote machine is redundant. Developers already
have a capable agent on their own machine. What's missing is a safe, token-lean way for that agent to
reach the machines it tests on:

- **No secrets in context.** Targets hold *references* to the OS keychain, `op://` or ssh-agent.
  Secrets are resolved inside Conning at the last moment and never returned by any tool.
- **Lean results.** Exit code first, output capped at 8 KB by default (the agent may ask for more, up
  to a ceiling), with a handle to page the rest. Fan-out to many targets collapses identical results.
- **Guardrails in code, not in the prompt.** Each target has a mode (`observe`, `ask`, `lease`).
  Commands outside the allowlist wait for your approval; "always allow" remembers two words, so
  `systemctl status` never lets through `systemctl stop`.
- **Plain OpenSSH underneath.** Linux and Windows (OpenSSH + PowerShell 7), pinned host keys,
  forwarding forced off.

## Install

```sh
uv tool install conning        # or: pipx install conning
conn mcp install claude        # planned: writes the MCP entry for claude, codex or cursor
```

The MCP server needs no install at all:

```sh
claude mcp add conning -- uvx conning mcp
```

## The agent's four tools

| Tool | What it does |
|---|---|
| `targets(filter?, check?)` | One line per target: name, OS, shell, tags, mode. Never a host, user or secret. |
| `run(target, cmd \| argv, wait=30, max_bytes=8192, ...)` | Runs on one target, a list or `tag:<tag>`. Exit code first. Still running after `wait` seconds: returns a job id (`wait=0` is async). |
| `read(id, wait?, range?, grep?, signal?)` | Long-polls a job for new lines, pages a saved output, or reads a remote file. |
| `transfer(source, dest)` | Copies files between `local:<path>` and `<target>:<path>`, checked by sha256. |

Agents without MCP can use the same commands through the `conn` CLI; the output is identical.

## For agents: CLI reference

This block is generated by `conn help --markdown`, so you don't need to call `--help`. A test keeps it
in sync with the code.

<!-- conn-help:start -->
```
conn targets [--check] [filter]
    List targets: name, OS, shell, tags, mode. Never hosts or secrets.

conn run [--wait WAIT] [--timeout TIMEOUT] [--cwd CWD] [--shell]
                [--max-bytes MAX_BYTES] [--grep GREP]
                target [argv ...]
    Run a command on one target, a list, or tag:<tag>. Exit code first.

conn read [--wait WAIT] [--range RANGE] [--grep GREP] [--signal {INT,TERM,KILL}]
                 [--max-bytes MAX_BYTES]
                 id
    Page a job (new lines only), a saved output, an approval, or a remote file.

conn transfer source dest
    Copy files: local:<path> to <target>:<path>, or back. sha256 checked.

conn add [--host HOST] [--user USER] [--port PORT] [--auth {ssh-agent,key,password}]
                [--secret SECRET] [--key KEY] [--os {linux,windows,darwin}]
                [--mode {observe,ask,lease}] [--tag TAG] [--retry]
                name
    Add a target. Without a terminal it is saved as pending until a human approves it.

conn approve [--always] what
    Human only: make a pending target live, or allow a pending command a:<id>.

conn import [--match MATCH]
    Import hosts from ~/.ssh/config as pending targets (unsafe options dropped).

conn rm name
    Remove a target and its pinned host key.

conn test name
    Probe a target: reachability, OS, shell, pinned host key.

conn lease [--minutes MINUTES] name
    Human only: give a target a full shell for a time box (1-60 minutes).

conn watch
    Live control room: every command on every target, and approval prompts.

conn doctor
    Check setup: agent permission rules, weak passwords, unpinned host keys.

conn mcp <serve|install> ...
    Run the MCP server on stdio, or install it into an agent client.

conn help [--markdown]
    Show this help; --markdown prints the block cached in README.md.
```
<!-- conn-help:end -->

A target you add with `conn add` from an agent session is saved as **pending**. It does nothing until
the human runs `conn approve <name>`, which shows the host, the pinned host-key fingerprint and where
the secret comes from.

A command outside a target's allowlist returns `status=pending_approval id=a:<id>`. The human answers
with `conn approve a:<id>` (allow once, always allow its first two words, or deny), and the agent picks
up the result with `read a:<id>`.

## Safety model

| Mode | What the agent can do | Default for |
|---|---|---|
| `observe` | Allowlisted read commands only; everything else is refused. | targets tagged `shared` or `prod` |
| `ask` | Allowlisted commands run; anything else waits for your approval. | new lab targets |
| `lease` | Any command, for a time box you grant (15 min default, 60 max). | never by default |

- No tool returns a secret, adds a live target or changes policy.
- Secrets travel over stdin or the SSH channel's env, never argv. Output is redacted before it is saved.
- Remote output is marked untrusted. Shell wrappers (`sh -c`, `python -c`, `sudo`...) and shell syntax
  (`;`, `|`, `$(...)`) always ask.
- `conn mcp install` also denies the agent raw `ssh`/`scp`, so it can't go around Conning.
- The audit log is hash-chained. It runs as your user, so it is tamper-evident, not tamper-proof.
